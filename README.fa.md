# WebSpider

**بگذارید هوش مصنوعی در مرورگر برایتان کار کند. فقط بگویید چه می‌خواهید — بقیه‌اش با WebSpider.**

WebSpider یک عامل هوش مصنوعی در پنل کناری کروم است که **مرورگر واقعی** شما را می‌گرداند:
صفحه را می‌خواند، کنترل‌ها را می‌شناسد، کلیک و تایپ می‌کند، داده استخراج می‌کند، ممیزی
می‌گیرد، کارِ خودش را تأیید می‌کند و وقتی یک مدل از کار بیفتد خودش مدل بعدی را امتحان
می‌کند. بدون نرم‌افزار جانبی، بدون داشبورد ابری — یک افزونه و کلید API خودتان.

## چرا WebSpider

بیشتر ابزارهای «مرورگر هوش مصنوعی» یک جعبهٔ چت هستند که به صفحه چسبانده شده‌اند. کنترل‌ها
را نمی‌بینند، انتخاب‌گرهای CSS را حدس می‌زنند، و وقتی یک کلیک بی‌سروصدا هیچ کاری نمی‌کند با
خوشحالی می‌گویند «انجام شد». WebSpider برعکس این فرض ساخته شده: **عاملی که نمی‌تواند کاری
را که کرده اثبات کند، عامل نیست.**

به همین دلیل هر کنترل یک `elementId` پایدار می‌گیرد، بعد از هر کنشِ تغییردهنده یک
خواندنِ تازهٔ وضعیت صفحه انجام می‌شود، و نتیجه می‌گوید صفحه واقعاً عوض شد یا نه. اگر عوض
نشده باشد، WebSpider همان را می‌گوید — نه اینکه آن را موفقیت حساب کند.

## نصب

۱. `chrome://extensions` را باز کنید و **Developer mode** را روشن کنید.
۲. روی **Load unpacked** بزنید و همین پوشه را انتخاب کنید.
۳. **WebSpider** را به نوار ابزار پین کنید و رویش کلیک کنید (یا `Alt+Shift+W` را بزنید).
۴. **تنظیمات ← اتصال** را باز کنید، آدرس پایهٔ سازگار با OpenAI و کلید API را وارد کنید و
   **ذخیره و آزمایش** را بزنید.

چیزی برای ساختن و وابستگی‌ای برای نصب وجود ندارد — افزونه فقط HTML، CSS و JavaScript است.

## شروع سریع

۱. هر صفحه‌ای را که می‌خواهید باز کنید.
۲. در پنل، خواسته‌تان را به زبان ساده بنویسید — مثلاً
   «این صفحه را بررسی کن، مشکلات اصلی را پیدا کن و یک خلاصهٔ کوتاه بنویس.»
۳. **ارسال** را بزنید. مرحله‌به‌مرحله ببینید که WebSpider بازرسی، کنش و تأیید می‌کند.
۴. هر درخواست تأییدی را پاسخ دهید و اگر کپچایی بود خودتان حلش کنید — اجرا همان لحظه
   خودکار ادامه می‌یابد.

## اتصال مدل

WebSpider با پروتکل **Chat Completions** سازگار با OpenAI حرف می‌زند، پس هر سرویس سازگار
کار می‌کند.

| | |
| --- | --- |
| **آدرس پایه** | مثلاً `https://api.openai.com/v1` — مسیرهای `/chat/completions` و `/models` از آن ساخته می‌شوند. |
| **کلید API** | فقط در `chrome.storage.local` روی رایانهٔ خودتان ذخیره می‌شود. هرگز لاگ نمی‌شود و هرگز در پیام خطا نشان داده نمی‌شود. |
| **سازگار با** | OpenAI، Azure OpenAI، OpenRouter، Groq، DeepSeek، Together، Mistral، Ollama، LM Studio، vLLM و هر دروازهٔ سازگار با OpenAI دیگر. |

روی **ذخیره و آزمایش** بزنید تا WebSpider فهرست مدل‌ها را بگیرد، سلامت‌شان را بسنجد و
تأخیر را گزارش کند. اگر `/models` در دسترس نبود، شناسهٔ مدل را دستی در همان زبانه وارد
کنید. کلید API شما **فقط** به همان آدرسی که خودتان تنظیم کرده‌اید فرستاده می‌شود.

## ابزارهایی که عامل در اختیار دارد

**خواندن و بازرسی**

| ابزار | چه می‌دهد |
| --- | --- |
| `page_snapshot` | نمای ساختاریافتهٔ صفحه با `elementId` پایدار برای کنترل‌ها |
| `page_state` | خواندنِ سبک وضعیت به‌همراه هش محتوا، برای «چیزی عوض شد؟» |
| `page_diagnostics` | خطاهای صفحه، خطاهای کنسول، تصاویر شکسته، منابع کند، لینک‌های مشکوک |
| `query_elements` | فهرست ساختاریافته برای هر انتخاب‌گر CSS (نقش، نام، متن، ابعاد، نمایش) |
| `get_table` | سرستون‌ها، سطرها، یا آبجکت‌های کلیددار بر اساس سرستون |
| `get_form` | فیلدها با برچسب، مقدار، اجباری‌بودن، گزینه‌ها و وضعیت اعتبارسنجی |
| `find_in_page` | تطبیق‌های متنی با زمینهٔ اطراف و عناصر دربرگیرندهٔ آن‌ها |
| `get_selection` | متنی که کاربر انتخاب کرده است |
| `console_logs` | پیام‌های کنسول که در دنیای JavaScript خودِ صفحه ضبط شده‌اند |
| `dialog_log` | فراخوانی‌های `alert` / `confirm` / `prompt` که صفحه باز کرده است |
| `network_log` | زمان‌بندی منابع، حجم انتقال، وضعیت کش |
| `styles_of` | استایل محاسبه‌شده، پس‌زمینهٔ مؤثر، نسبت کنتراست WCAG |
| `audit` | `seo` · `a11y` · `perf` · `links` · `content` · `all`، امتیازدهی و رتبه‌بندی‌شده |
| `extract` | متن خوانا، HTML، لینک‌ها یا جدول از یک ناحیه |
| `mark_page` / `diff_page` | اثبات دقیق اینکه چه چیزی تغییر کرد |

**کنش روی صفحه** — `navigate` · `open_tab` · `back` · `forward` · `click` · `click_at` ·
`type` · `clear_field` · `select` · `check` · `hover` · `focus` · `press_key` ·
`submit_form` · `scroll` · `scroll_to` · `highlight` · `draw` · `screenshot`

**انتظار و تأیید** — `wait` · `wait_for_element` · `wait_for_text` · `wait_for_dom_stable` ·
`wait_for_network_idle`

**ایمنی و کنترل** — `detect_human_check` · `human_verification` · `ask_confirmation` ·
`set_dialog_policy` · `sync_browser_target`

اسنپ‌شات‌ها هر کنترل را با یک `elementId` پایدار برچسب می‌زنند و عامل اول سراغ همان‌ها
می‌رود، که بسیار مطمئن‌تر از حدس زدن انتخاب‌گر CSS است.

## حالت‌ها

| حالت | چه می‌کند |
| --- | --- |
| **Agent** | توان کامل — صفحه را می‌خواند و روی آن کنش می‌کند. |
| **Plan** | بررسی می‌کند و یک نقشهٔ مرحله‌به‌مرحله می‌دهد. فراخوانی‌های ابزار در نوبت اول دور ریخته می‌شوند، پس یک نقشه هرگز نمی‌تواند صفحه را تغییر دهد. |
| **Research** | گردآوری شواهد فقط‌خواندنی. کنش‌ها رد می‌شوند؛ عامل فقط می‌خواند، استخراج می‌کند و ممیزی می‌گیرد. |

## سرعت و دقت

| تنظیم | پیش‌فرض | اثر |
| --- | --- | --- |
| سرعت اجرا | متعادل | `سریع` تأیید پس از کنش را رد می‌کند و بیشتر کش می‌کند؛ `دقیق` هرگز کش نمی‌کند و بعد از هر کنش دوباره می‌خواند. |
| تأیید صفحه بعد از هر کنش | روشن | به هر کنشِ تغییردهنده یک بلوک `after` می‌چسباند. |
| استفادهٔ مجدد از اسنپ‌شات تازه | روشن | وقتی عامل چند بار بازرسی می‌کند یک رفت‌وبرگشت صرفه‌جویی می‌شود. |
| توقف برای کپچا و ادامهٔ خودکار | روشن | هرگز کپچا را حل نمی‌کند؛ متوقف می‌شود و ادامه می‌دهد. |

فراخوانی‌های فقط‌خواندنی که در یک نوبت صادر شوند **هم‌زمان** اجرا می‌شوند. هر فراخوانی
تغییردهنده یک سد است، پس همان ترتیبی که مدل خواسته، همان ترتیبی است که صفحه می‌بیند.

## تأیید انسانی و کپچا

WebSpider چالش‌های تأیید انسانی را **تشخیص** می‌دهد — reCAPTCHA، hCaptcha، Cloudflare
Turnstile، Arkose، GeeTest، DataDome، PerimeterX، AWS WAF و MTCaptcha — نام سرویس‌دهنده را
می‌گوید، اجرا را متوقف می‌کند و صفحه را نشانتان می‌دهد. سپس صفحه را می‌پاید و **همان لحظه
که حلش کردید از همان مرحله ادامه می‌دهد**.

هرگز چالشی را حل، کلیک، تفسیر یا دور نمی‌زند. این یک تصمیم طراحی است، نه قابلیت جامانده:
کپچا یک کنترل امنیتی است و خودکار کردنش راه را برای ساخت انبوه حساب و سوءاستفاده باز می‌کند.

## حریم خصوصی

> آنچه روی صفحهٔ شما دیده می‌شود، روی رایانهٔ شما می‌ماند.

- **بدون تلمتری، بدون آنالیتیکس، بدون حساب کاربری، بدون درخواست به‌روزرسانی خودکار.**
- **محتوای صفحه محلی خوانده می‌شود.** تنها بایت‌هایی که از رایانهٔ شما بیرون می‌روند همان
  چیزهایی است که مدل برای پاسخ به درخواستتان لازم دارد، و **فقط** به آدرسی که خودتان
  تنظیم کرده‌اید فرستاده می‌شوند.
- **کلید API** در `chrome.storage.local` می‌ماند و هرگز لاگ یا بازگو نمی‌شود.
- **گفتگوهای شما** به‌صورت محلی در `chatSessions` ذخیره می‌شوند و از کشوی تاریخچه قابل
  خروجی‌گرفتن یا حذف هستند.

## پیش‌نیازها

**برای اجرا:** کروم ۱۱۴ یا بالاتر (Manifest V3 و API پنل کناری). چیز دیگری لازم نیست —
نه مرحلهٔ ساخت، نه وابستگی، نه سرویس پس‌زمینه.

**برای توسعه:** هر ویرایشگر متنی. برای اجرای مجموعهٔ آزمون به Node 22+ و `jsdom` نیاز دارید.

## معماری

| فایل | نقش |
| --- | --- |
| `manifest.json` | مانیفست MV3: پنل کناری، سرویس‌ورکر، کانتنت‌اسکریپت، پل MAIN-world |
| `main.js` | پل MAIN-world (`document_start`): ضبط کنسول و دیالوگ‌های بومی |
| `sidepanel.html` | نشانه‌گذاری پنل و اسپرایت آیکون SVG |
| `style.css` | توکن‌های طراحی، هر دو پوسته، چیدمان با خصوصیات منطقی |
| `sidepanel.js` | ماشین وضعیت رابط، رندر، i18n، فهرست ابزار، ذخیره‌سازی، خروجی |
| `background.js` | حلقهٔ عامل، استریم SSE، سوییچ مدل، توزیع ابزار، تأیید |
| `content.js` | عامل صفحه: مکان‌یابی، اسنپ‌شات، خواننده‌ها، ممیزی‌ها، کنش‌ها، انتظارها، لایه‌ها |

گفتگوها در `chrome.storage.local` با کلید `chatSessions` ذخیره می‌شوند و وضعیت زندهٔ عامل
`agentState` است. کلیدهای ذخیره‌سازی بخشی از قرارداد داده‌اند — تغییر نام یکی، تاریخچه را
از بین می‌برد.

`content.js` در دنیای ایزوله اجرا می‌شود و JavaScript صفحه را نمی‌بیند. `main.js` در دنیای
خودِ صفحه اجرا می‌شود و آنچه ضبط می‌کند را از طریق شکاف‌های DOM
(`#__webspider_console`، `#__webspider_dialogs`) برمی‌گرداند — این دو دنیا DOM را مشترک
دارند، نه heap جاوااسکریپت را.

| `check-syntax.mjs` | همهٔ فایل‌ها parse می‌شوند؛ آیکون‌ها، کلیدهای i18n و انتخاب‌گرهای DOM پیدا می‌شوند؛ سیم‌کشی ابزارها کامل است؛ مانیفست معتبر است |
| `test-core.mjs` | تجزیهٔ آدرس، ناورداهای کوتاه‌سازی پیام، مونتاژ SSE، مسیر بدون استریم، شِمای ابزارها، پروفایل‌های سرعت، نگهبان تأیید انسانی، و یک اجرای کامل با مدل استاب‌شده |
| `test-panel.mjs` | پنل واقعی در jsdom: راه‌اندازی، کنش‌های سریع، حالت‌ها، i18n، پوسته، استریم، ماندگاری، حذف، میان‌بر، فهرست ابزار، تنظیمات اجرا، خروجی |
| `test-content.mjs` | کانتنت‌اسکریپت واقعی در jsdom: شناسه‌های اسنپ‌شات، کنش‌ها، انتظارها، خواننده‌ها، ممیزی‌ها، تشخیص کپچا، سخت‌سازی توزیع |

**۶۶۱ assertion به‌همراه ۱۲ بررسی استاتیک، همه سبز.** مرحلهٔ استاتیک چهار نگهبان بین‌فایلی
دارد: توزیع سرویس‌ورکر ↔ هندلر کانتنت، ابزار اعلام‌شده ↔ شاخهٔ `act()`، ابزار اعلام‌شده ↔
فهرست پنل، و ثبت پل MAIN-world در مانیفست.

هر نگهبان در این مجموعه با تزریق باگی که باید بگیرد اعتبارسنجی شده — نگهبانی که با باگِ
خودش هم سبز بماند، تزئین است نه آزمون.

## رفع اشکال

| نشانه | راه‌حل |
| --- | --- |
| «API Key is missing» | **تنظیمات ← اتصال** را باز کنید، کلید را بچسبانید و **ذخیره و آزمایش** را بزنید. |
| «All verified models and endpoints failed» | آدرس پایه، کلید و شبکه را بررسی کنید. پنل آخرین خطای هر مدل را نشان می‌دهد. |
| عامل می‌گوید صفحه «تغییر نکرد» | کلیک به جایی نخورده است. از آن بخواهید اسنپ‌شات بگیرد یا `page_diagnostics` را اجرا کند. |
| اجرا متوقف می‌شود و یک چالش نشان می‌دهد | همان دروازهٔ کپچاست. در صفحه حلش کنید — اجرا خودش ادامه می‌دهد. |
| پنل کناری باز نمی‌شود | افزونه را پین کنید و روی آیکونش کلیک کنید، یا `Alt+Shift+W` را بزنید. |
